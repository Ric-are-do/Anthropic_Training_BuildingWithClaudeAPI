# MCP Server Inspector

The MCP Inspector is a standalone web UI tool for testing your MCP server directly — without needing the client, Claude, or a full application setup. It works with any MCP server regardless of language, so it works just as well with our TypeScript server as it does with the Python version.

Since the server and client are separate, the inspector lets you verify that your server tools are working correctly before you even touch the client code. Think of it like Postman for your MCP server — you can confirm your tools behave as expected in isolation, without needing `listTools()` or `callTool()` in the client to be implemented yet.

## Starting the Inspector

Run the following command from the project root:

```bash
npx @modelcontextprotocol/inspector npx tsx mcp/mcp-server.ts
```

This spawns your MCP server and opens a web UI where you can interact with it directly.

---

## Connecting and Testing Tools

Click the **Connect** button on the left side to start your MCP server. Once connected, you'll see a navigation bar with sections for Resources, Prompts, Tools, and other features.

To test your tools:

1. Navigate to the **Tools** section
2. Click **List Tools** to see all available tools
3. Select a tool to open its testing interface
4. Fill in the required parameters
5. Click **Run Tool** to execute and see the results

---

## Testing Document Operations

For example, to test the `read_document` tool, enter a document ID like `deposition.md` and run the tool. The inspector shows the result including any returned content or error messages.

You can also chain operations to verify functionality. For instance:

1. Run `edit_document` to replace the content of a document
2. Immediately run `read_document` on the same doc to confirm the changes were applied correctly

This makes it easy to verify that your tools are working together as expected.

---

## Development Workflow

The inspector creates an efficient development loop:

1. Make changes to your MCP server code
2. Test individual tools through the inspector
3. Verify results without needing a full application setup
4. Debug issues in isolation

This tool becomes essential as you build more complex MCP servers. It eliminates the need to wire up your server to Claude or another application just to test basic functionality, making development much faster and more focused.
